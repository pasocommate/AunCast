# モニタリングと上限調整（スタッフ向け）

スタッフ画面では、インスタンス全体の再生・再同期の状況をリアルタイムに確認できます。これを読み取り、必要に応じて[接続上限](../concepts/connection-limit.md)を調整するのがスタッフの主な役割です。

![スタッフ操作画面](../assets/portable-panel-staff.png){ width="360" }

---

## 画面の見方

### 状態インジケーター（右側の色付き表示）

全員の状態を **色** でまとめて示す領域です。全体が安定しているか、何か発生しているかを一目で把握できます。色のおおよその意味は次のとおりです。

| 色 | 意味 |
|---|---|
| 白 | 正常に再生中 |
| 青 | 再同期の順番待ち |
| 黄 | 再同期の実行中 |
| 橙 | 接続中（読み込み中） |
| 赤 | エラー |

記号の **塗り** は、その観客が再生中か停止中かを示します。

| 形 | 意味 |
|---|---|
| ■（塗り） | 再生中 |
| □（枠） | 停止中 |

つまり１つの記号で、**色＝再同期の状況**、**塗り／枠＝再生中か停止中か** を同時に示しています。

!!! tip "色による読み取りの要点"
    - **青が多い** → 多数が順番待ち。Resync Allの直後や、配信が乱れた直後に発生します。
    - **赤が増加** → エラーが多発。配信元・配信サーバー・URLを疑います。
    - **黄が多い** → 枠を最大限に使って順次処理中。これは正常な「混雑」状態です。

!!! note "配信を停止すると全員赤になります（正常）"
    OBSなどで配信（ソース）を停止すると、各クライアントが再接続を試み続けるため、インジケーターが **全員赤** になります。これは **故障ではありません**。配信を終えたら **Stop All** で停止してください（→ [配信・運用上の注意](streaming.md)）。

### 人数の表示（Playing / Instance / Queued）

| 表示 | 意味 |
|---|---|
| **Playing** | 現在再生できている人数（接続中を含む） |
| **Instance** | インスタンス内の人数 |
| **Queued** | 再同期の順番待ちの人数 |

### Playing（配信中のURL）

現在配信中のURLを表示します。意図した配信が流れているかの確認に使用します。

### 完了の見込み時間

順番待ちがあるときは、**全体の再同期が完了するまでの見込み時間** が表示されます。観客のパネルにも、各自の順番が来るまでの目安が表示されます。

## 接続上限の調整 {#limits}

スタッフはその場で２つの数値を変更できます（変更は全員に反映されます）。それぞれ **Edit** ボタンで編集します。

| スタッフ画面の表示 | 意味 | 設定の目安 |
|---|---|---|
| **Connections（接続数）** | 配信サーバーが受け付けられる上限接続数 | 契約している **配信プランの上限** に合わせる（例: 100）。配信中に頻繁に変える値ではなく、基準として正しい値を入力する |
| **Concurrent（同時実行数）** | 同時に再同期してよい人数 | 空き接続と安定度を見て **10〜15** 程度から |

### 同時実行数（Concurrent）の決め方

基本的な考え方は次のとおりです。

```
おおよその空き接続 ＝ Connections − 現在の再生人数
Concurrent は、その空き接続より十分に小さく
```

!!! example "80名が視聴中・上限100の例"
    - 再生中80名 → 空き接続は約20。
    - 再同期中の観客は一時的に２本目を使うため、**Concurrent は空き接続よりかなり小さめ** に設定します。
    - 出発点は **10〜15** 程度。配信が安定していて速く回したい場合は上げ、不安定な場合は下げます。

### 増減の目安

| 状況 | 対応 | 理由 |
|---|---|---|
| Resync Allの完了が遅すぎる | Concurrent を **上げる** | 一度に処理できる人数が増え、早く完了する |
| エラー（赤）が増えた | Concurrent を **下げる** | 配信サーバーへの一度の負荷を減らし、成功率を上げる |
| 人数が増えた | Concurrent を **下げる** 方向で見直す | 再生中が増えると空き接続が減る |
| 配信プランを変更した | Connections を更新 | 計算の基準を実態に合わせる |

!!! warning "上げすぎに注意"
    Concurrent を空き接続より大きくすると、再同期で配信サーバーの上限を超過し、**かえって失敗が増えます**。「早く完了させたい」からと上げすぎないでください。判断に迷う場合は下げるほうが安全です。

## 全員完了までの見込み

Resync Allの実行前に、おおよその所要時間を見積もれます。

```
全員完了の目安 ＝ （人数 ÷ Concurrent）を切り上げ × 1 回あたり約 8 秒
```

| 人数 | Concurrent | 目安 |
|---|---|---|
| 40 | 10 | （40÷10）× ８＝ 約32秒 |
| 80 | 10 | （80÷10）× ８＝ 約64秒 |
| 80 | 15 | （80÷15）× ８＝ 約48秒 |

!!! note "あくまで目安です"
    １回あたりの時間は配信やネットワークの状況で変動します。実際の見込みは画面の完了時間表示で確認してください。

## 異常を検知したとき

| 画面の状況 | 想定される原因 | 対応 |
|---|---|---|
| 赤が散発的 | 一部の観客の一時的なエラー | 経過観察。各自の Resync で復旧することが多い |
| 赤が広範囲・増加が続く | 配信を停止した（正常）／配信元・配信サーバー・URLの問題 | 配信停止直後なら **Stop All**。そうでなければ Playing を確認しURLを入れ直す。最終手段で Reboot All |
| 青が多く減らない | 順番待ちが滞留 | Concurrent を上げる。配信サーバーに余裕があるか確認 |
| 全体が停止 | 配信が停止している／URLが不正 | Playing を確認し、URLを入れ直す |

操作方法は[操作パネルの使い方](operations.md)を参照してください。
