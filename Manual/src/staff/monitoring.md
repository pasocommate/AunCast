# モニタリングと上限調整（スタッフ向け）

スタッフ画面では、インスタンス全体の再生・再同期のようすをリアルタイムで見られます。これを読み取って、必要なら[接続上限](../concepts/connection-limit.md)を調整するのがスタッフの主な役目です。

![スタッフ操作画面](../assets/portable-panel-staff.png){ width="360" }

---

## 画面の見方

### 状態インジケーター（右側の色つき表示）

全員の状態を **色** でまとめて表す部分です。ひと目で「全体が落ち着いているか／何か起きているか」が分かります。色のおおよその意味は次のとおりです。

| 色 | 意味 |
|---|---|
| 白 | 正常に再生中 |
| 青 | 再同期の順番待ち |
| 黄 | 再同期の実行中 |
| 橙 | 接続中（読み込み中） |
| 赤 | エラー |

記号の **塗り** は、その人が再生中か停止中かを表します。

| 形 | 意味 |
|---|---|
| ■（塗り） | 再生中 |
| □（枠） | 停止中 |

つまり 1 つの記号で、**色＝再同期の状況**、**塗り／枠＝再生中か停止中か** を同時に表しています。

!!! tip "色での読み取りのコツ"
    - **青がたくさん** → 多くの人が順番待ち。Resync All の直後や、配信が乱れた直後に起きます。
    - **赤が増えていく** → エラーが多発。配信元・配信サーバー・URL を疑います。
    - **黄がいっぱい** → 枠をフルに使って順番に処理中。これは正常な「混んでいる」状態です。

### 人数の表示（Playing / Instance / Queued）

| 表示 | 意味 |
|---|---|
| **Playing** | いま再生できている人数（接続中を含む） |
| **Instance** | インスタンス内の人数 |
| **Queued** | 再同期の順番待ちの人数 |

### Playing（再生中の URL）

いま流れている配信 URL を表示します。意図した配信が流れているかの確認に使います。

### 完了の見込み時間

順番待ちがあるときは、**全体の再同期が終わるまでの見込み時間** が表示されます。視聴者のパネルにも、各自の順番が来るまでの目安が出ます。

---

## 接続上限の調整 {#limits}

スタッフはその場で 2 つの数字を変更できます（変更は全員に反映）。それぞれ **Edit** ボタンで編集します。

| スタッフ画面の表示 | 意味 | 決め方の目安 |
|---|---|---|
| **Connections（接続数）** | 配信サーバーが受け付けられる上限人数 | 契約している **配信プランの人数** に合わせる（例: 100）。配信中にコロコロ変える数字ではなく、基準として正しい値を入れる |
| **Concurrent（同時実行数）** | 同時に再同期してよい人数 | 空き席と安定度を見て **10〜15** くらいから |

### 同時実行数（Concurrent）の決め方

基本の考え方はこうです。

```
だいたいの空き席 ＝ Connections − いま再生中の人数
Concurrent は、その空き席より十分小さく
```

!!! example "80 人が見ている・上限 100 の例"
    - 再生中 80 人 → 空き席は約 20。
    - 再同期する人は一時的に 2 本目を使うので、**Concurrent は空き席よりかなり小さめ** にする。
    - 出発点は **10〜15** くらい。配信が安定していて速く回したいなら上げ、不安定なら下げます。

### 上げる・下げるの目安

| こんなとき | どうする | なぜ |
|---|---|---|
| Resync All の完了が遅すぎる | Concurrent を **上げる** | 一度にさばける人数が増え、早く片付く |
| エラー（赤）が増えた | Concurrent を **下げる** | 配信サーバーへの一度の負荷を減らし、成功しやすくする |
| 人数が増えた | Concurrent を **下げる** 方向で見直す | 再生中が増えると空き席が減る |
| 配信プランを変えた | Connections を更新 | 計算の基準を実態に合わせる |

!!! warning "上げすぎ注意"
    Concurrent を空き席より大きくすると、再同期で配信サーバーの上限を超えて、**かえって失敗が増えます**。「早く片付けたい」と上げすぎないでください。迷ったら下げるほうが安全です。

## 全員終わるまでの見込み

Resync All を押す前に、だいたいの所要時間を見積もれます。

```
全員終わる目安 ＝ （人数 ÷ Concurrent）を切り上げ × 1回あたり約8秒
```

| 人数 | Concurrent | 目安 |
|---|---|---|
| 40 | 10 | （40÷10）× 8 ＝ 約 32 秒 |
| 80 | 10 | （80÷10）× 8 ＝ 約 64 秒 |
| 80 | 15 | （80÷15）× 8 ＝ 約 48 秒 |

!!! note "あくまで目安"
    1 回あたりの時間は配信やネットワークの状況で変わります。実際の見込みは画面の完了時間表示で確認してください。

## おかしいと思ったら

| 画面のようす | 考えられること | 対応 |
|---|---|---|
| 赤がちらほら | 一部の人の一時的なエラー | 様子見。各自の Resync で直ることが多い |
| 赤が広範囲・増え続ける | 配信元・配信サーバー・URL の問題 | Playing を確認。必要なら URL を入れ直す。最後の手段で Reboot All |
| 青が多く減らない | 順番待ちが滞っている | Concurrent を上げる。配信サーバーに余裕があるか確認 |
| 全体が止まっている | 配信が止まっている／URL が不正 | Playing を確認し、URL を入れ直す |

操作そのものは[操作パネルの使い方](operations.md)を参照してください。
