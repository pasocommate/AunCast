# 配信・運用上の注意（スタッフ／設置者向け）

このページは、AunCast を安定して運用するために、**配信そのものや設定にまつわる注意点**をまとめます。映像の停止・再同期の多発は、AunCast 側だけでなく **配信のやり方や設定が原因**のことも多く、ここを押さえると全体の安定度が大きく変わります。

---

## 配信サーバー（CDN）の選び方

!!! tip "本番は VRCDN の有料プランを推奨"
    低遅延で安定した配信には、**VRCDN の有料プラン**を推奨します。低遅延で安定しており、同時接続数のプランも明確です。

**TopazChat** は無料で使えますが、その分**利用者が多く**、**昼は空いていても夜は混雑して遅延が増える**ことが多いです。テスト配信や、遅延にシビアでないイベントには十分使えますが、**遅延が重要な本番イベントでは VRCDN 有料プランを推奨**します。

CDN の同時接続上限はプランによって決まります。スタッフ画面の **Connections** を契約プランの値に合わせてください（→ [同時接続上限の管理](../concepts/connection-limit.md)）。

---

## 配信ビットレートは十分に下げる

OBS などのエンコーダーは、**利用する配信サービス（CDN）の推奨設定値を参考に**設定してください。そのうえで、**映像ビットレートは十分に下げる**ことが安定運用の要点です。

!!! warning "OBS のプリセット（6000 Kbps 等）は大きすぎます"
    OBS には、映像ビットレートが **6000 Kbps** などに設定されたプリセットがあります。**この値は低遅延ライブには大きすぎて不安定**になります。配信サービスの推奨値を参考に、**しっかり下げて**ください。

- **高すぎる**：回線の弱い視聴者でバッファリング・停止が起き、再同期が多発 → 接続枠を圧迫して全体が不安定化。
- **低すぎる**：画質が落ちる。

最適値は配信内容・視聴者層・CDN プランで変わるため、**本番前のテスト配信で確認**することを推奨します。

!!! note "ビットレートの揺らぎにも注意"
    ビットレートが安定せず大きく上下すると、再生位置のズレ（Drift）や停止が増え、再同期が多発します。エンコード設定はできるだけ安定させてください。

---

## 配信 URL を漏らさない／自動再生は原則オフ

配信 URL が外部に漏れると、**インスタンス外（別インスタンス・別ワールド）から接続**される可能性があります。その結果、**予定していた同時接続数を超えてしまい**、配信全体が不安定になる恐れがあります。

!!! warning "URL の共有は最小限に"
    - 配信 URL は **必要な範囲のスタッフだけ**で共有してください。
    - 公開チャンネルへの貼り付けや、配信画面への URL の映り込みに注意。
    - 漏れた疑いがある場合は、**新しい URL のストリームに切り替えて**、スタッフ画面の Next URL → 送信（Promote）で差し替えてください（→ [操作パネルの使い方](operations.md)）。

!!! danger "自動再生は基本的に使わないことを推奨"
    設置者向け設定の **「最初の Join で自動再生」**（デフォルト配信 URL）を有効にしていると、**別インスタンスを立てられるだけで配信に接続**してしまい、それだけで**同時接続数が超過**し得ます。

    そのため、**基本的に自動再生機能は使用しない**ことをおすすめします。配信はスタッフが手動で開始してください（Next URL → 送信）。どうしても使う場合は、インスタンスが乱立しない運用（イベント時のみ・限定公開など）とセットで検討してください。

この設定は設置者が AunCastSettings で切り替えます（→ [導入とパラメータ設定](../setup/install.md)）。

---

## 配信を終えるときは Stop All

OBS などで配信（ソース）を停止しても、AunCast 側は各クライアントが**再接続を試み続けます**。そのためスタッフ画面のインジケーターは**全員赤**になり、視聴者には「問題が発生しています」系の表示が出続けます。

!!! note "全員赤は故障ではありません"
    配信を止めた直後にインジケーターが全部赤くなるのは、各自が再接続を試みている**正常な挙動**です。異常と見間違えないでください。

放置すると再接続を繰り返して接続枠を無駄に使うため、**配信を終えたら [Stop All](operations.md)** で全員の再生を停止することをおすすめします。配信を再開するときは、改めて Next URL → 送信（Promote）で流してください。

## まとめ

| 注意点 | 何が起きるか | 対策 |
|---|---|---|
| CDN の選択 | 無料リレーは夜間に混雑して遅延増 | 本番は **VRCDN 有料プラン**。TopazChat はテスト・低要求イベント向け |
| ビットレート | 高すぎ＝停止・再同期多発／低すぎ＝低画質 | 推奨値を参考に**十分下げる**。OBS の 6000 Kbps 等は要注意。テスト配信で確認 |
| URL 漏えい | インスタンス外から接続され同時接続超過 | 共有は最小限。漏れたら URL 差し替え |
| 自動再生 | 別インスタンスを立てられるだけで接続超過 | **原則オフ**。配信はスタッフが手動開始 |
| 配信終了時 | 全員赤（再接続継続・正常） | 配信を止めたら **Stop All** |
