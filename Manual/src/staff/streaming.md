# 配信・運用上の注意（スタッフ／ワールド制作者向け）

このページでは、AunCast を安定して運用するために、**配信そのものや設定に関する注意点**をまとめます。**主役である音声**の途切れ・ズレや、映像の停止、再同期の多発は、AunCast 側だけでなく **配信の方法や設定に起因する**ことも多く、ここを押さえると全体の安定度が大きく変わります。

---

## 配信サーバー（CDN）の選定

!!! tip "本番は VRCDN の有料プランを推奨"
    低遅延で安定した配信には、**VRCDN の有料プラン**を推奨します。低遅延で安定しており、同時接続数のプランも明確です。

**TopazChat** は無料で利用できますが、その分 **利用者が多く**、**昼間は空いていても夜間は混雑して遅延が増える**傾向があります。テスト配信や、遅延にシビアでないイベントには十分使用できますが、**遅延が重要な本番イベントでは VRCDN の有料プランを推奨**します。

CDNの同時接続上限はプランによって決まります。スタッフ画面の **Connections** を契約プランの値に合わせてください（→ [同時接続上限の管理](../concepts/connection-limit.md)）。

---

## 配信ビットレートは十分に下げる

OBSなどのエンコーダーは、**利用する配信サービス（CDN）の推奨設定値を参考に**設定してください。そのうえで、**映像ビットレートを十分に下げる**ことが安定運用の要点です。

!!! warning "OBSのプリセット（6000 Kbps等）は過大です"
    OBSには、映像ビットレートが **6000 Kbps** などに設定されたプリセットがあります。**この値は低遅延ライブには過大で、不安定化の原因**になります。配信サービスの推奨値を参考に、**十分に下げて**ください。

- **高すぎる**：回線の弱い観客でバッファリング・停止が発生し、再同期が多発 → 接続枠を圧迫して全体が不安定化。
- **低すぎる**：画質が低下する。

最適値は配信内容・観客層・CDNプランによって変わるため、**本番前のテスト配信で確認**することを推奨します。

!!! note "ビットレートの変動にも注意"
    ビットレートが安定せず大きく変動すると、再生位置のズレ（Drift）や停止が増え、再同期が多発します。エンコード設定はできるだけ安定させてください。

---

## 配信URLを漏らさない／自動再生は原則オフ

配信URLが外部に漏れると、**インスタンス外（別インスタンス・別ワールド）から接続**される可能性があります。その結果、**想定していた同時接続数を超過し**、配信全体が不安定になる恐れがあります。

!!! warning "URLの共有は最小限に"
    - 配信URLは **必要な範囲のスタッフのみ**で共有してください。
    - 公開チャンネルへの掲載や、配信画面へのURLの映り込みに注意してください。
    - 漏えいの疑いがある場合は、**新しいURLのストリームに切り替え**、スタッフ画面のNext URL → 上下矢印ボタン（Promote）で差し替えてください（→ [操作パネルの使い方](operations.md)）。

!!! danger "自動再生は原則として使用しないことを推奨"
    ワールド制作者向け設定の **「最初のJoinで自動再生」**（デフォルト配信URL）を有効にしていると、**別インスタンスが立てられるだけで配信へ接続**し、それだけで **同時接続数が超過** し得ます。

    そのため、**原則として自動再生機能は使用しない**ことを推奨します。配信はスタッフが手動で開始してください（Next URL → 上下矢印ボタン）。やむを得ず使用する場合は、インスタンスが乱立しない運用（イベント時のみ・限定公開など）と併せて検討してください。

この設定はワールド制作者が AunCastSettings で切り替えます（→ [導入とパラメータ設定](../setup/install.md)）。

---

## 配信を終えるときはStop All

OBSなどで配信（ソース）を停止しても、AunCast 側は各クライアントが **再接続を試み続けます**。そのためスタッフ画面のインジケーターは **全員赤** になり、観客には「問題が発生しています」系の表示が出続けます。

!!! note "全員赤は故障ではありません"
    配信停止の直後にインジケーターが全て赤くなるのは、各自が再接続を試みている **正常な挙動** です。異常と見誤らないでください。

放置すると再接続を繰り返して接続枠を浪費するため、**配信を終えたら [Stop All](operations.md)** で全員の再生を停止することを推奨します。配信を再開する際は、改めてNext URL → 上下矢印ボタン（Promote）で配信してください。

---

## まとめ

| 注意点 | 起こり得ること | 対策 |
|---|---|---|
| CDNの選定 | 無料リレーは夜間に混雑し遅延が増加 | 本番は **VRCDN 有料プラン**。TopazChat はテスト・低要求イベント向け |
| ビットレート | 高すぎ＝停止・再同期多発／低すぎ＝低画質 | 推奨値を参考に **十分下げる**。OBSの6000 Kbps等は要注意。テスト配信で確認 |
| URL漏えい | インスタンス外から接続され同時接続超過 | 共有は最小限に。漏れたらURLを差し替え |
| 自動再生 | 別インスタンスが立つだけで接続超過 | **原則オフ**。配信はスタッフが手動開始 |
| 配信終了時 | 全員赤（再接続継続・正常） | 配信を止めたら **Stop All** |
